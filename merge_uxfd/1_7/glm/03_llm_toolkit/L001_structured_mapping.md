## 背景

### 现状描述
- Toolkit 输出结构化解释（JSON 格式）
- 工程师需要自然语言说明

### 为什么需要合并
- 将技术特征转换为易懂的文本
- 作为对话系统的输入

### 当前问题
- 映射规则未定义
- LLM 接入方式未确定

---

## 合并任务分解

### 子任务 1: 定义映射规则（特征→文本）
- [ ] 定义 13 种统计特征的语义描述
  - 例: Mean → "信号的直流分量或平均振动水平"
- [ ] 定义频率特征的映射
  - 例: 峰值频率 → "检测到 XHz 处的显著峰值"
- [ ] 定义模型输出的映射
  - 例: 分类结果 → "检测到 [故障类型]"

**验收标准**: 特征→文本映射表完成

### 子任务 2: 实现模板化解释生成
- [ ] 创建 `src/llm_explainable/templates.py`
- [ ] 实现基于模板的解释生成（不依赖 LLM）
- [ ] 实现基于 LLM 的解释生成

**验收标准**: 两种方式都能生成解释

### 子任务 3: 支持国产 LLM（Deepseek/GLM-4）
- [ ] 实现 Deepseek API 接入
- [ ] 实现 GLM-4 API 接入
- [ ] 添加配置化选择机制

**验收标准**: 两个 LLM 都能调用

---

## 选项

### 选项 A: 模板 + LLM 混合（推荐 ★）
- **描述**: 默认使用模板，复杂查询调用 LLM
- **优点**: 成本低，响应快
- **缺点**: 模板灵活性有限

### 选项 B: 纯 LLM
- **描述**: 所有解释都通过 LLM 生成
- **优点**: 灵活性高
- **缺点**: 成本高，可能延迟

### 选项 C: 纯模板
- **描述**: 不使用 LLM，只用模板
- **优点**: 零成本，零延迟
- **缺点**: 解释质量有限
