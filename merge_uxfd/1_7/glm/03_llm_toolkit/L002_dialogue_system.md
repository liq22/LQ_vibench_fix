**所属 Paper**: 🟣 LLM_Explainable_FD_Toolkit
**分类**: 组件实现
**优先级**: P2
**依赖**: L001

## 背景

### 现状描述
- 工程师可能对诊断结果有追问
- 需要多轮对话支持

### 为什么需要合并
- 提升工程师使用体验
- 支持解释深度探索

### 当前问题
- 对话状态管理未实现
- 意图识别未实现

---

## 合并任务分解

### 子任务 1: 对话状态管理
- [ ] 设计对话会话数据结构
  - session_id, messages, signal_data, diagnosis_result
- [ ] 实现对话历史存储
- [ ] 实现上下文检索（最近 N 轮）

**验收标准**: 能保存和检索对话历史

### 子任务 2: 意图识别
- [ ] 定义意图类型
  - 技术细节追问
  - 维护建议
  - 原因解释
- [ ] 实现简单的规则分类器
  - 基于关键词匹配
- [ ] 可选: 实现 LLM 意图分类

**验收标准**: 能识别用户问题类型

### 子任务 3: 上下文保持
- [ ] 实现上下文摘要生成
- [ ] 限制 token 使用（避免超长上下文）
- [ ] 实现对话轮次限制

**验收标准**: 多轮对话能保持连贯

---

## 选项

### 选项 A: 简单规则 + LLM（推荐 ★）
- **描述**: 意图识别用规则，生成用 LLM
- **优点**: 平衡成本和效果
- **缺点**: 规则需要维护

### 选项 B: 纯规则
- **描述**: 完全基于预定义规则
- **优点**: 简单，可控
- **缺点**: 灵活性差

### 选项 C: 纯 LLM
- **描述**: 所有对话逻辑由 LLM 处理
- **优点**: 最灵活
- **缺点**: 成本高
