# L003: 幻觉防护机制

**所属 Paper**: 🟣 LLM_Explainable_FD_Toolkit
**分类**: 组件实现
**优先级**: P1
**依赖**: L001

---

## 背景

### 现状描述
- LLM 可能生成不准确或虚构的解释
- 工业场景对准确性要求高

### 为什么需要合并
- 确保解释的可信度
- 提供失败的降级方案

### 当前问题
- 幻觉检测未实现
- 降级机制未实现

---

## 合并任务分解

### 子任务 1: 输出必须携带证据字段
- [ ] 定义证据字段格式
  - `evidence`: 源自结构化解释的原始数据
  - `confidence`: 置信度
  - `source`: 数据来源
- [ ] 强制 LLM 输出包含证据
- [ ] 解析并验证证据完整性

**验收标准**: 所有解释都有证据字段

### 子任务 2: 事实一致性检查
- [ ] 检查数值是否在合理范围
- [ ] 检查故障类型是否在预定义列表
- [ ] 检查频率引用是否正确

**验收标准**: 能检测明显错误

### 子任务 3: 失败时回退到模板化输出
- [ ] 实现回退逻辑
  - LLM 失败 → 使用模板
  - 一致性检查失败 → 使用模板
- [ ] 记录失败原因

**验收标准**: 任何情况下都有输出

---

## 选项

### 选项 A: 完整防护（推荐 ★）
- **描述**: 实现证据字段、一致性检查、回退机制
- **优点**: 最安全
- **缺点**: 工作量大

### 选项 B: 基础防护
- **描述**: 只实现证据字段和回退
- **优点**: 简单
- **缺点**: 一致性检查缺失

### 选项 C: 仅回退
- **描述**: 只实现失败回退
- **优点**: 最简单
- **缺点**: 幻觉可能无法检测
