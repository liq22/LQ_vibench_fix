# T003: 模型适配器实现

**所属 Paper**: 🟢 Explainable_FD_Toolkit
**分类**: 组件实现
**优先级**: P1
**依赖**: T001

---

## 背景

### 现状描述
- 现有模型（TSPN, Fusion1D2D, MoE 等）需要适配统一的解释 API
- 各模型内部结构不同，需要适配器模式

### 为什么需要合并
- 让所有模型能输出统一格式的可解释性结果
- 支持模型扩展

### 当前问题
- 适配器模式未实现
- 注册机制未定义

---

## 合并任务分解

### 子任务 1: 为 TSPN 创建适配器
- [ ] 继承 `BaseExplainer`
- [ ] 实现 TSPN 的 `explain()` 方法
  - 输出: 算子激活权重、信号路径
- [ ] 编写单元测试

**验收标准**: TSPN 适配器可用

### 子任务 2: 为 Fusion1D2D 创建适配器
- [ ] 继承 `BaseExplainer`
- [ ] 实现 Fusion1D2D 的 `explain()` 方法
  - 输出: 融合权重、1D/2D 特征归因
- [ ] 编写单元测试

**验收标准**: Fusion1D2D 适配器可用

### 子任务 3: 为 MoE 创建适配器
- [ ] 继承 `BaseExplainer`
- [ ] 实现 MoE 的 `explain()` 方法
  - 输出: 专家激活权重、路径签名
- [ ] 编写单元测试

**验收标准**: MoE 适配器可用

### 子任务 4: 适配器注册机制
- [ ] 实现 `ExplainerRegistry` 类
- [ ] 支持模型名称 → 适配器类的映射
- [ ] 提供统一的 `get_explainer(model)` 入口

**验收标准**: 注册表可用

## 选项

### 选项 A: 实现 Wave 1 模型适配器（推荐 ★）
- **描述**: 先实现 TSPN/Fusion1D2D/MoE，其他模型后续补充
- **优点**: 覆盖核心模型
- **缺点**: 其他模型需要补充

### 选项 B: 实现所有模型适配器
- **描述**: 一次性实现所有模型的适配器
- **优点**: 一次性完成
- **缺点**: 工作量大

### 选项 C: 仅实现 TSPN
- **描述**: 只做 TSPN 适配器
- **优点**: 最快
- **缺点**: 功能不全
